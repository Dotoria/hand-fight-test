# 손 제스처 마법 프로토타입 — 계획서

## 목적
렐루게임즈 "AI 통합 게임 개발자" 지원용 포트폴리오.
(공고: https://job-boards.greenhouse.io/relugames/jobs/8554538002)

한 문장 목표: **웹캠 손 인식을 게임 입력으로 쓰되, 흔들리는 인식 결과를 게임이 믿을 수 있는 입력으로 바꾸는 과정을 설계하고 수치로 검증한다.**

공고 업무와의 대응
| 공고 업무 | 이 프로젝트에서 |
|---|---|
| 입력 파이프라인 (센서·플레이어 행동 → 모델 입력) | 웹캠 → 모델 입력 텐서, 관절 좌표 → 게임용 특징값 |
| 출력 후처리 (모델 응답 → 게임 규칙·연출) | 신뢰도 기준, 유지 시간, 쿨타임, 손 사라짐 처리 |
| 상태 관리 | 제스처 인식 상태 머신 |
| 가설 기반 빠른 프로토타이핑 | 가설 → 측정 → 재설계 기록 (README) |
| 문화: Evaluate, Silent Failure 경계 | 녹화 영상 테스트 세트 + 지표 자동 측정 |
| 우대: 병목·성능 개선 | 추론 주기·해상도별 FPS / 추론 ms 측정 |

## 게임: 가위바위보 상성 마법
- 적이 불·물·풀 속성으로 다가옴 → 상성이 맞는 손 모양(주먹·보·가위)을 잠깐 유지해 막음
- 손 모양 유지 중 게이지가 차오름 (인식 지연을 "시전 시간"으로 연출)
- 시스템이 지금 어떤 손 모양으로 인식 중인지 항상 화면에 표시
- 시전자 캐릭터 연출은 스프라이트/파티클로 (선택)

## 기술 선택 (1일차에 결정)
1. **Unity Inference Engine + BlazeHand (먼저 시도)**
   - https://huggingface.co/unity/inference-engine-blaze-hand
   - 순수 Unity 패키지, 텐서 전처리/후처리를 직접 다룸 → "모델 입출력 경험" 증거로 가장 강함
   - 확인할 것: 현재 Unity 버전(6000.0.34f1)과 패키지 호환, 예제가 손 감지만 하는지 21개 관절까지 주는지
2. **MediaPipe Unity Plugin (대안)**
   - https://github.com/homuler/MediaPipeUnityPlugin
   - Hand Landmarker 지원, 샘플 씬 풍부. 네이티브 라이브러리라 에디터 크래시 가능성
- 결정 기준: 2일차 안에 웹캠에서 관절 좌표가 안정적으로 나오면 채택, 아니면 대안으로 전환

## 구조
```
IFrameSource (WebcamSource / VideoClipSource)   ← 검증 때 녹화 영상을 같은 파이프라인에 흘리기 위함
  → HandInference      : N프레임마다, 낮춘 해상도로, 비동기
  → HandFeatures       : 손목 기준 이동 + 손 크기 정규화, 손가락별 펼침 여부 (struct, 매 프레임 할당 없음)
  → GestureClassifier  : 규칙 기반 (주먹/보/가위/없음) + 점수
  → GestureStabilizer  : 신뢰도 기준, N ms 유지 시 발동, 발동 후 쿨타임, 손 사라짐 처리 (상태 머신)
  → Game               : 상성 판정, 게이지, 피드백
  + DebugOverlay       : 관절 표시, 신뢰도, 현재 상태, 추론 ms, FPS
```
- 규칙 기반으로 시작하는 이유: 학습 데이터 불필요, 틀린 이유를 설명 가능. README에 이유 기록
- 튜닝 값(유지 시간, 신뢰도 기준, 추론 주기 등)은 ScriptableObject 하나에 모음

## 검증
- 테스트 세트: 짧은 영상 30개 이상 (조명·거리·배경·왼손/오른손 다양하게) + **아무 제스처도 하지 않는 영상** 포함
- 정답 라벨: 영상별 기대 제스처를 파일명 또는 CSV로
- 지표 (CSV로 자동 기록)
  - 정확도: 의도한 제스처로 인식됐나
  - 오발동: 제스처 없는 영상에서 분당 잘못 발동 횟수
  - 반응 시간: 손 모양을 만든 순간 → 발동까지 ms
- 파라미터를 바꿀 때마다 결과를 `docs/eval-log.md`에 표로 누적 (트레이드오프를 숫자로)

## 일정 (5일)
| 일차 | 할 일 | 완료 기준 |
|---|---|---|
| 1 | 패키지 세팅, 모델·앵커 배치, 문서 작성 | 모델이 ModelAsset으로 임포트되고 레포가 정리됨 |
| 2 | 웹캠 연결, 관절 추출, 특징·규칙 분류, 디버그 화면 | 세 손 모양이 화면에 구분 표시 |
| 3 | 안정화 상태 머신, 게임 연결 | 적을 상성 마법으로 막을 수 있음 |
| 4 | 녹화 영상 테스트 세트, 측정 도구 | 세 지표 자동 기록 |
| 5 | 수치 기반 튜닝, README, 30~60초 데모 영상 | 제출 가능 상태 |
| 추가 | Android 빌드, 추론 주기·해상도별 FPS 측정 | 여유 있을 때 |
